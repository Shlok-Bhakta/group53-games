# Group 53 Games

Small multiplayer games for one friend group from Discord. Chess (classic, four-player, and real-time versions of both), Scrabble (2 to 8 players, async or live with a turn timer) and Poker (Hold'em, Omaha, Short Deck and 5-Card Draw, async) are live, Golf (turn-based or live, on handmade or generated courses, plus practice holes and an open world) is live, and Stonks is a stock-market game: $10,000 each to trade anything on Yahoo Finance, live; PvP Wordle is next. Every game lives in the same app.

## Who this is for

- **At most 5 players, maybe 10.** Never design for scale. A full table scan, a query that returns everyone, or a cron that touches every row is fine. Use this headroom to make the games richer, not to optimize.
- **Phones only.** Everyone plays from the installed PWA on iOS or Android. Desktop only needs to not break. Design for thumbs: tap targets at least 44px, primary actions 56px, nothing important in tiny menus, and confirm anything destructive.
- **Everyone is a software developer.** Programmer jokes and references land, and so do themes like Catppuccin, Gruvbox and Nord.
- **Low friction.** Every extra tap or screen costs players. Prefer one-tap actions, sensible defaults, and flows that resume where people left off.

## Design principles

- **Lean on Convex's live updates.** Every query is a live subscription: when the database changes, every connected client re-renders instantly. Build features on that. Show other players' moves the moment they happen, presence ("Chris is typing a guess"), live scoreboards, attacks landing on your board in real time, and animations triggered by someone else's action. If a feature could be live, make it live.
- **Spend compute freely.** The group is tiny, so server work is basically free. Recompute derived state on every change, fan out notifications generously, render images on demand, and schedule as many functions as needed.
- **Make it interactive and PvP.** Games should let players affect each other: sabotage, steal, block, taunt. Async is fine, since games run over a day rather than in one sitting, but whatever is happening should feel live.
- **Notifications are core.** Push is how players hear they've been hit or that it's their turn. Games stay locked until push is on. When something happens to a player, notify them.
- **Discord is home.** Players sign in with Discord, links get shared in Discord, and link previews should show live game state (see `og/`).

## Stack

- React 19, Vite, React Router, Tailwind v4 and shadcn/ui (Radix). The shared parts are listed under Design system below; use them instead of hand-rolled controls.
- Self-hosted Convex on kiwi with SQLite, plus Convex Auth with the Discord provider.
- Web push through `web-push` in a Node action (`convex/push.ts`).
- `og/`: a small Node service that renders Discord and Open Graph previews with satori and resvg.
- `stonks/`: a small Rust service (the stonks sidecar), the only thing that talks to Yahoo, streaming prices into Convex for Stonks.

## Games framework

Adding a game means: its entry in `GAMES` and its modes in `convex/modes.ts`, its server file (`convex/<game>.ts`, built on `convex/lib/`), its hooks in `convex/games.ts`, its link preview board in `convex/previews.ts` (`BOARDS`) and `og/server.mjs`, and its entry in `src/games/index.tsx`. `hooksFor` and `BOARDS` are typed by `GameKey`, so leaving a game out of either fails to compile. Everything else is shared.

- `convex/modes.ts` (shared by server and client) lists `GAMES` (name, path and the ways a game ends) and every mode (`ModeDef`). Each mode is `async` (turn-based over hours) or `realtime` (everyone on screen at once), has `players` (most seats) and `minPlayers`, and its `settings`. Optional: `draws` (players can offer a draw; Classic and Real-time chess), `wants` (the crew push reads "Chris wants <wants>", the title otherwise) and `reasons` (endings worded differently in this mode). Read the optional ones with `modeDef(mode)`. An unknown mode is an error everywhere (`gameOf` throws).
- **Endings.** `matches.result.reason` is a key in the game's `reasons` (checkmate, went_out, hands...), the mode's, or the shared ones (resign, timeout, last_player, agreement). `reasonOf(reason, mode)` gives the `label` on screen, the `push` wording ("Classic chess vs Chris: checkmate.") and, where it reads well, `won` ("by checkmate"), which link previews put after the winner's name.
- **Seats.** When `minPlayers` equals `players` (chess) the game starts by itself once full. When they differ (Scrabble, 2 to 8) the lobby waits for the host to tap Start (`matches.startGame`), and it also starts by itself if every seat fills. Challenges in these games leave the other seats open without pinging the crew.
- **Settings.** Each mode lists its settings (choices with a default, each a number, plus a `short` summary like "9 tiles"). The host picks them on the mode page (remembered per mode on the phone) and can still change them in the lobby (`matches.configure`, which merges only the keys sent), where everyone sees them change. `matches.settings` stores only what differs from the defaults; read it with `settingsOf(mode, match.settings)`. Rematches keep the settings. Chess has: Time to move (classic: none, 1, 2 or 3 days, losing on time; four-player: 1 to 3 days, default 2), and real-time Cooldown and Piece speed (`State.pace` in the engine). Scrabble has the settings listed under Scrabble below.
- **Game hooks** (`convex/games.ts`): `seats` (seat colors in turn order; `SEAT_COLORS` in `convex/lib/seats.ts` for games that only need one color each), `start` (set up `state`, whose turn, first pushes), `resign`, `timeout` (an async move timer ran out), `timeoutWarning`, and optionally `unstarted` (a real-time game still waiting for everyone to open the board, which `matches.sweep` calls off after 3 minutes). `matches.ts` calls these and never names a game. Hooks are looked up at call time because the game files import `matches.ts`.
- **Shared server helpers** (`convex/lib/`), so a game file is only its rules:
  - `seats.ts`: `requireUser` (every "Sign in first."), `loadMatch`, `seated(ctx, id, { game, modes?, active?, as? })` (the signed-in player's `{ userId, match, seat, color }`, or an error saying why not) and `onTurn` (the same, and it's their turn), plus `seatOf`, `isPlayer`, `opponentsOf`, `playerWith`.
  - `turns.ts`: `passTurn(ctx, match, { state, turn, by, push?, timer?, patch? })` saves a move, bumps `moveCount`, pushes the next player (unless they made the move) and arms their clock: the 8-hour reminder, or a live game's turn timer (`timer`, like Scrabble's `turnTimeout`). A move by someone not on turn that leaves the turn where it was (a resignation) changes none of that, so the player to move keeps their reminder and strikes; it returns `fresh` to say which. Also `armTurn`, `scheduleReminder`, and `startPushes` (a game's opening pushes, none on rematches).
  - `secrets.ts` and `drafts.ts`: `readSecret`, `writeSecret`, `mySecret` (the owner's, for a query); `readDraft`, `writeDraft`, `clearDraft`, `draftsOf`, `myDraft`.
  - `people.ts`: `displayName` ("Someone" if gone), `namesOf`, `person` (name and picture).
  - Outside `lib/`: `notifyMatch(ctx, userId, match, { title, body, url? })` in `convex/notify.ts` fills in the game's path and tag (`matchTag`), and `finishBySeats(ctx, match, groups, reason)` in `matches.ts` ends a game by groups of seats, best first.
- **Secrets** (`secrets` table, `convex/lib/secrets.ts`): state players mustn't see. Per player (`userId` set; a Scrabble rack) or the game's (no `userId`; the tile bag). Only ever returned to its owner; never put hidden information in `matches.state`, since everyone can read that.
- **Drafts** (`drafts` table, `convex/lib/drafts.ts`): a player's plan for their next move, saved as they go, so it's there when they come back. Private, but `count` lets others see that someone is planning.
- Paths come from `matchPath(match)`, `acceptPath(match)` and `modePath(mode)`, which use the game's path (`/chess/...`, `/scrabble/...`). Never hard-code a game's path.
- `convex/matches.ts` is game-agnostic and works for any seat count: open lobbies and the queue (`queue` joins someone waiting or opens a lobby and pings the crew), challenges to one or more players (invite fewer than the seats and the rest are `openSeats` for the crew; invited players keep their seat until they answer, and in bigger games a decline opens the seat instead of cancelling), join, leave, decline, cancel, resign, draw offers (modes with `draws`), `finish` (results with `standings` for multiplayer, ratings, placing pushes), rematches (everyone has to say yes; colors move one seat along), and the `lobby`, `attention` and `inbox` queries. Mode-specific state lives in `matches.state`.
- Client side, `src/games/index.tsx` (`GAME_UI`) gives each game its Games card art, mode art, rules (a function of the settings) and the in-game screen. Routes are generated from it in `App.tsx`: `/<game>` is `GameHub` (`src/pages/GameHub.tsx`), `/<game>/mode/:slug` is `ModePage`, and `/<game>/:id` is `MatchScreen`, which shows the shared lobby (`src/components/match/`: seats, settings, Start, share, cancel) or the game's own screen. Every game screen has the same hamburger menu (`GameMenu` in `src/components/GameMenu.tsx`, sliding in from the right): whatever the game adds on top, then every setting the game is played with (changed ones in the primary color), how to play, and Share. `MatchScreen` puts it in the nav bar's action slot; a fullscreen game opens it from its own button with its own sections (Scrabble's scores and words, `ScrabbleMenu`). The result, standings with points, rating change, rematch and the resign confirmation are shared there too. Lists that can mix games label modes "Chess Classic", "Scrabble Live" (`fullModeLabel`).
- Four tabs (`src/components/TabBar.tsx`, a full-width bar whose active pill slides between tabs): **Home** (`src/pages/Home.tsx`), **Games** (`src/pages/Games.tsx`), **Crew**, and **You** (profile and settings).
- Home is built on `matches.inbox`, across every mode: Challenges (answered in place), Your turn, Open seats, Your ratings (stat cards from `ratings.mine`, only modes you've played), Waiting, and Happening now (`watch`). A section only appears when it has something in it; with nothing going on, Home shows an idle tile row and a Find a game button.
- Games has one card per game with its art playing in once (`ChessBanner`, the WORDLE tiles), who's playing it right now, and Play. Play opens the game's own pages; nothing about starting a game is a drawer.
- A game's page (`GameHub`) shows the mode cards from `ModePicker` (`src/components/ModePicker.tsx`), grouped Async and Real-time, each with its art, a badge when something waits there, and my Elo; a game with one mode of each kind shows the two side by side. Then the crew's recent games of it (`matches.recent`). The mode page is the full-page menu for one mode: Find a game (joins a waiting game or opens one for the crew; "Open a game" for games the host starts), Settings, Challenge (the crew inline: two-player modes send on one tap, bigger games let you pick several), How to play, open seats, your games, games happening now, the mode's leaderboard, and recent games. Old `/chess?mode=` and `/?new=` links land on the mode page.
- Leaderboards live on each mode's page, not on Crew, so adding games never piles more tabs or pills onto one screen.
- Each mode has one name, used everywhere: Classic, 4-Player, Real-time, Real-time 4-Player (`MODES[mode].name`).
- The app icon shows a badge: my moves plus challenges waiting (`navigator.setAppBadge`). Pushes carry the count (`badgeCount` in `convex/notify.ts`, set in `public/sw.js`), and `useAppBadge` keeps it right while the app is open. It works on iOS 16.4+ home screen apps once notifications are allowed.
- Deep links: challenge and lobby pushes point at `acceptPath` (`/chess/:id?accept=1`), and opening that takes the seat. Notification taps reach the app through `public/sw.js`, which posts `{type: "navigate"}` to an open window (iOS standalone apps ignore `WindowClient.navigate()`) and also leaves the URL in the Cache API, which `src/deepLinks.ts` picks up when the app opens fresh at its start page. Links shared in Discord open in a browser, not the app: iOS can't open a home screen web app from a link at all, and Android only sometimes can (Discord's in-app browser usually keeps the link). That browser isn't signed in either. So a game link opened outside the app shows the link page (`src/components/LinkHandoff.tsx`, above the install steps): the game, then the crew's faces under "Which one's you?". Tapping yours pushes the game to your phone (`links.handoff`, at most once every 15 seconds per player), and the notification opens the app right in it and takes the seat. Android also gets an "Open in the app" button (an `intent://` link), and the manifest asks Chrome to capture links into the installed app (`handle_links`, `launch_handler`). `links.preview` and `links.handoff` work signed out on purpose and only show what a Discord link preview already does. Challenges also wait on Home.
- Async turns: every move pushes the next player, and `scheduleReminder` re-arms an 8-hour reminder (both through `passTurn`). Reminders carry the move count they were set for and fizzle if anyone has moved since, so they never need cancelling. Someone else resigning doesn't reset the clock of the player to move.
- `notify()` (`convex/notify.ts`) skips the push when the player is already looking at that URL. Pushes carry a `tag` per match so they replace each other.
- Ratings: Elo per mode in `convex/ratings.ts` (K=32, start 1200). Multiplayer games count every pair of players as a game between them, weighted K/(n-1), by placing (`multiElo`). The leaderboard lists the whole crew.
- Async chess (Classic and 4-Player) never sends a move straight off the board: the move waits on that phone, shown as the position after it with a faint copy of the piece at home, and Confirm (naming the move) and Cancel take the place of draw and resign in the dock (`src/games/chess/dock.tsx`). While it waits you can move another piece instead, or move the same one back home to take it back. A move landing, a resignation or a timeout drops it. Real-time chess moves at once. Under the board of both async modes is the move line (`src/games/chess/history.tsx`), with an arrow at each end to step back and forward, and tapping a move shows the board just after it. Stepping back stays put when a move lands, and a tap on the board goes back to now. Four-player boards are replayed by `fourBoards` (`convex/chess/four/classic.ts`), which trusts the recorded moves and puts back who'd gone out by each ply, because replaying through `move4` took over a second for 200 moves.
- Chess: `convex/chess.ts`. Classic is validated with chess.js. Real-time follows rtchess.org (Kung Fu Chess) and runs on a deterministic engine in `convex/chess/realtime.ts`, shared by server and client: 30 ticks/s, 1 square per second, 5s cooldown, collision captures, premoves (a busy piece queues one move that fires when it's ready; a `cancel` command drops it), take the king to win. Keep the engine free of Convex and browser imports.
- Four-player chess (chess.com Free-for-all) lives in `convex/chess/four/`: `board.ts` (14x14 minus 3x3 corners; red, blue, yellow, green clockwise; each army's setup is red's rotated) and `classic.ts` (the turn-based engine: check against every opponent, checkmate/stalemate put you out, grey armies stay on the board and score nothing, points for captures and multi-checks, most points wins, ties by who lasted longer). `chess:fourMove` validates with it; in four-player, resigning or six missed reminders (48 hours, `TIMEOUT_STRIKES`) puts you out and play goes on. The real-time engine takes a `variant` ("two" or "four"): in four-player, losing your king (or a `resign` command) freezes your army in grey, there's no castling, and the last king standing wins with a ranking by elimination tick.
- Scrabble: `convex/scrabble.ts` on top of `convex/scrabble/engine.ts`. The rules (legal plays, the words a play forms, scoring with bonus squares, blanks and the 50-point bingo, letter values, the bag, the standard board) come from `@bglowacki/bingo-engine` (MIT, pinned to 0.1.0), wrapped in `evaluate()`, which turns our free-form placements (tiles on any squares) into the engine's line-plus-tiles form. On top of it we add a 21×21 board (our own layout, handed to the engine as its `BoardLayout`) and a Letter League rules mode (`LEAGUE` in the engine; the same engine, board and word list with Letter League's changes on top). So far that's sticky bonuses ("Wild" scoring): a bonus square stays with its tile, so every later word through it scores it again, scored from the engine's per-word cell breakdown. Add further Letter League rules to `LEAGUE`. The engine runs with a dictionary that accepts anything; the server checks words against `convex/scrabble/words.ts` (ENABLE, public domain, plus qi/za/ok/ew; server-only, regenerate with `scripts/gen-words.sh`) through `isWord`, and phones ask `scrabble.check` for the live preview. Settings: Tiles in hand (5/7/9; a bingo is the whole rack), Tiles in the bag (Half to 200), Board (15×15 or 21×21), Rules (Scrabble or Letter League), Rounds (no limit, 5, 10, 15), and Time to move (async, skips you when it runs out) or Turn timer (live, 30s to 3m; `scrabble:turnTimeout` skips the turn). It ends when someone goes out with the bag empty (they get everyone's leftover tiles), when everyone has passed twice in a row, or after the last round; leftover tiles count against their holder. Places by score, and Elo through `multiElo`. Resigning puts your tiles back in the bag and you place last; the rest play on.
- The Scrabble screen (`src/games/scrabble/`), laid out like Letter League: a game in progress takes the whole screen (`fullscreen` in `GAME_UI`, so `MatchScreen` leaves out its nav bar). The board is the whole background, running under the status bar (the page sets `data-fullbleed`, which hides `TopEdge`), and everything else floats over it: a back button, a pill edged in the color of whoever's turn it is (their avatar with its frame, the last play and the live clock), and a menu button on top (`TopBar.tsx`), and a see-through dock at the bottom. The board knows how much of it the bars cover (`view.padTop`/`padBottom`): any square can be panned into the open part between them, and drops only land in that open part. The menu slides in from the right: everyone's score, whose turn it is and who's planning, the words played (tap one for its definition, from dictionaryapi.dev), then the shared settings, how to play and Share, and Resign, kept away from the buttons you tap all game. The dock holds your rack and, under it, the bag (tiles left; tap it for every letter you haven't seen yet), Swap (pick nothing and it becomes Pass), Play (which names the word and score) and Shuffle or Recall. A finished game goes back to the board above the result. The board (`Board.tsx`) pinches, double-taps and drags to zoom and pan (moves go straight to the DOM), starts zoomed in on the action, and glides to a new word that lands out of view. Tap a rack tile then a square, or drag it (it sits right under your finger); tap a placed tile to send it back, drag it to move it, and drag over the rack to reorder. Plans work any time, even on someone else's turn, are saved as drafts (a moment after each change), and come back on any phone; a tile whose square someone else takes goes back to your rack with a toast. Like Letter League, whoever's turn it is shows up on everyone else's board as face-down tiles in their color where they're trying things (`scrabble.planning` returns squares, never letters), appearing and vanishing in little puffs. The score bubble and tile outlines are green for real words and red otherwise. Blanks ask for their letter in a small sheet. Tiles are physical cream tiles in every theme (`.stile` in `style.css`), edged in the color of whoever played them. It should feel alive: a played word drops in tile by tile and bounces in time with its notes, its score floats up in the player's color, the scores pop as they change, tiles thunk onto the board and spring when moved, a held tile jiggles and leans the way you drag it, shuffling makes the rack hop, words that aren't real shake, and a bingo spells BINGO over the board.
- Poker: `convex/poker.ts` on top of `convex/poker/engine.ts` (pure, shared with phones: blinds, betting order with heads-up button-as-small-blind, min-raise and short all-ins that don't reopen raising, pot limit, side pots, uncalled bets refunded, the draw, resigning, busts, standings) and `convex/poker/cards.ts` (hand ranking: best five of seven, Omaha's exactly two plus three, Short Deck's flush over full house and trips over straight). Four async modes, 2 to 8 players (Draw 2 to 6): Hold'em, Omaha (pot limit by default), Short Deck, 5-Card Draw. Settings: Chips (blinds start at 10/20 whatever it is, so more chips is a longer, deeper game), Hands (no limit by default, so it plays until one player has everything like a tournament; with a limit, most chips after the last one wins), Blinds go up every (2/3/5 hands or never) and Blinds multiply by (×1.25, ×1.5, ×2 or ×3, in round chips, `blindsFor`), Betting (no limit or pot limit) and Time to move (runs out: check or fold for you; `IDLE_OUT` = 3 in a row takes you off the table). The deck lives in the game's secret and each player's cards in theirs (with the hand number, so a phone never shows last hand's cards); matches.state only ever holds cards shown at a showdown. The next hand is dealt the moment one ends, inside the same mutation. While it isn't your turn you can line up Check/Fold, Check or Call N (a draft, `poker.plan`, tied to that hand and street); the server plays it the moment the action reaches you, so a table of people who've lined up moves runs itself. `poker.move` and `poker.plan` carry the hand and street the player saw and refuse stale taps. Places are by chips, then the knocked-out in reverse order. The screen (`src/games/poker/`) follows the game layout: nav bar, then a square felt in the theme's own green (physical cream four-color cards and chips in every theme: `PlayingCard` and `PokerChip` in `src/components/ui/playing-card.tsx`, styled by `.playing-card`, `.poker-chip` and `.poker-felt`) with the street, the pot and its pile of chips in the seats' colors, the deck, and the board; everyone else along the bottom rail (`table/Seat.tsx`, put together in `Table.tsx`: avatar with frame, glow and online dot, badge by the name, cards fanned behind, bet above) starting on my left; my tile; my cards, big, with my hand named live and its cards ringed; and the dock (Fold / Check or Call / Bet or Raise, with a sheet for the amount; while waiting, the lined-up moves and Resign). **The screen draws a show, not the state** (`useShow` in `show.ts`): one mutation can finish a hand and deal the next, so the phone plays what happened in order (chips in, swept to the pile, cards out one at a time, the showdown with the winning five lifted, a flush or better spelled in tiles, ALL IN in tiles, the payout, the shuffle and the deal), catching up to the newest state whenever it's done, and acts only once it has (`busy` holds the dock). `PACE` scales every timing in one place. A card is the real card from its first frame, flying from the deck to where it stays, and whatever flies away holds where it lands until it's removed, because snapping back for a frame shows as a blip. It jumps straight to the end when motion is reduced or the phone isn't looking. Last hand opens the showdown in a sheet. Link previews draw the table with the board and stacks.
- Golf games (`golf:turns` and `golf:live` in `convex/modes.ts`, the match part of `convex/golf.ts`, `convex/golf/round.ts`, `src/games/golf/GolfGame.tsx`): a round of 3 to 18 holes on the shared match framework. Each hole of a game is its own world (keyed `m:<match>:<hole>`, `golfWorlds.matchId`), made by `startHole` with every ball already on the tee holding what it carried over; its course is stored in `golfCourses` (built by the `golf:build` action from the settings, hole 1 first so the game starts while the rest are made; `golf:holes` serves them). The world's `rules` (`world.ts`): a ball that's sunk or has taken par plus four is `done` (out of the world, with its strokes and bag) instead of respawning; `knockFree` means a ball knocked by another ball or someone's item into a hazard goes back where it sat without a penalty stroke (`Sim.knocked`); `markR` means balls sitting near the cup are marked and other balls roll through them (items still hit). **Turn-based** (async): one ball at a time, whoever's farthest from the cup by walking distance (`convex/golf/distance.ts`, `nextUp` in `round.ts`), anyone who hasn't teed off first in honors order (best score on the last hole). The server tells every phone whose turn it is with a "turn" command, so the world itself ignores anyone else's shot or items (and a second shot in a turn, Coffee's putt while rolling aside); `act` refuses them too and stamps commands after the turn started. `golf:tick` (twice a second for game worlds) runs the world to now, passes the turn once the shooter's ball is done or has shot and everything's still (`roundTick`, `giveTurn` through `passTurn`), pushes anyone who got knocked, and ends the hole from the settled world once every ball's done (`endHole`: scores, bags, next hole or `finishBySeats` by fewest strokes). Statuses that last seconds in real time last until the victim's next turn here (`UNTIL_NEXT_TURN`: Flash Camera till their shot, Electromagnet, ice and honey till the owner's next turn). Coming back to the game catches you up (`GolfGame.tsx`, the replay in `useGolfLoop.ts`): each phone remembers the hole and tick it last watched (`golf-seen:<match>` in localStorage, written about once a second while live), and on opening, or coming back to the app, every shot since plays out in real time from a moment before it's hit, the waits skipped, the camera on the shooter and their whole path drawn, hole by hole with each finished hole's card, then it's live; Skip jumps to now. It plays from the hole's start (`golfStarts`, written by `startHole`) and its commands (`golf:history`). Time to shoot is No limit by default (the turn waits, with the usual 8-hour reminders); with a limit set, when it runs out the caddie (`bot.ts`, the best of a fan of shots, only going for the cup from a short putt away (`CADDIE_SINK`) and with shaky hands, so sitting out never pays, worked out in the `golf:caddie` action because it can take over a second, and put in by `caddieShoot` only if that ball still sits where it was) takes it (`golf:shotTimeout`); three in a row (the third push says so) and the caddie takes all their turns, straight off and without a "Your shot" push, till they open the game (`golf:here`, which also restarts a course that stopped building) or are looking at it. **Live** (real-time): everyone shoots whenever, the hole clock (`golf:holeClock`) picks up whoever's left with par plus four, so sitting it out never pays, and the next hole starts after a few seconds to see the scores. Resigning takes your ball off and you place last. Settings: Course (Generated, Bumper Plains, Cold Start), Holes, and for a generated course Terrain, Holes like (mini golf, fairways, both), Hazards and Seed; Item boxes and which Items (a `mask` setting), Ball hits, Safe near the cup, Time to shoot or Hole clock. Settings can be `kind: "seed"` (any number; 0 rolls one when the game's made, `withSeeds` in `matches.create`, a rematch rolls a new one, never remembered on the phone) or `kind: "mask"` (a bit per option), and `when` hides one that doesn't apply. The seed shows in the lobby, the game menu (copy it, or "Play these holes", a mode page link with `?settings=`) and finished games in lists. Right under the mode page's settings are the holes the next game will be played on (`GameUI.setup`, `HolesPreview.tsx`): a generated course gets a real seed there straight away (the dice rolls another), and the server makes its holes one at a time into `golfPreviews` (`golf:requestPreview`, the `golf:makePreview` action, `golf:preview`, keyed by `genKey`: seed, terrain, style, hazards), which a game started on that seed uses instead of making them again; a course made by hand shows at once. The lobby shows them too: the host under the seed in its settings, everyone else under the settings chips. Tap a hole for a bigger look. Previews nobody's touched in two days are cleared. The screen: the hole fullscreen (`GolfWorld` with a `round`: aiming only on your turn, the camera following whoever's shooting, still drawing once your ball's in), the turn in the top bar, the scorecard in the menu (`GolfMenu`, `Scorecard`), each hole's scores coming up over the next (`HoleCard`), and the shared result plus the card at the end.

- Golf's netcode is real-time chess's: anything a player does is one insert into `golfCommands` stamped with the tick they did it on (`act`, up to `MAX_LAG` back), never a write anyone else makes; every phone runs the world from the settled snapshot (`golfSnapshots`) plus the commands (`advance` in `convex/golf/world.ts`), so the only traffic is commands (a shot costs another phone about 8 KB, snapshot and presence included). Your own shot plays at once, whatever the connection's doing: the phone keeps its own unconfirmed commands (`n.pending`, merged by `withPending`) instead of using a Convex optimistic update, because the commands query is unloaded for a whole round trip every time the snapshot moves. On airplane wifi a shot in that gap sat still for over a second and then the ball jumped, or was already back on the tee. Someone else's shot arrives late, the phone rebuilds from the snapshot and glides each ball from where it was drawn to where it is (`EASE_S`, `EASE_FAR_S`; only sinking and going back to a tee jumps), and balls are drawn between ticks. A command counts from when it was taken if it lands within `MAX_LAG` (2s). Your own sink always shows its score, however late the news. "Slow connection" shows in the dock while a command's gone unconfirmed over `SLOW_MS`. `e2e/golf.spec.ts` holds every WebSocket message back to test this (`slowConnection`). `golf:tick` settles the snapshot once a second while anything moves (rewriting it only every 4s or when it goes still) and sleeps only when the world is quiet; the next command wakes it. A still world is "quiet" and `advance` jumps straight to the next command or timer, so an idle day costs nothing to catch up. The jump moves every ball's clock (`b.t`) to exactly what stepping would have, because moving obstacles and statuses are drawn and checked from it: without that they froze while everything was still and jumped on the next shot. Every phone must get the same world bit for bit, and iPhones (JavaScriptCore) and Android and the server (V8) disagree in the last bit of `Math.sin`, `cos`, `atan2`, `hypot` and `pow`, which a bumper turns into a different shot: the engine, the shapes and the maps use `convex/golf/dmath.ts` (built only from exact arithmetic) and never those. The engine (`convex/golf/engine.ts`, moved from `src/games/golf`, which re-exports it for the prototype) steps one ball (`stepBall`) with what it shares with others (boxes, bumpers, mines, lasers) changed in place; `world.ts` adds the players, commands, ball-on-ball hits, timers and `pack`/`unpack` for storage.
- Stonks (`convex/stonks.ts`, `convex/stonks/`, `src/games/stonks/`, the `stonks/` sidecar): the S&P 500's 20 biggest companies ranked by their share of the index, every trade live, pre-market and after hours too. It isn't in `GAMES`/`MODES` yet: a plain `GameCard` (`STONKS`, art in `StonksBanner.tsx`), `/stonks` is the board and `/stonks/:symbol` a stock. Phones only read; the sidecar is the only writer, through internal mutations (`stonks:ingest` for trades and how each source is doing, `stonks:series` for history and the day's and year's stats, `stonks:holdings` for the weights, `stonks:setProfile` for key stats and news) with the admin key, like `og`. Weights come from State Street's daily SPY holdings file (as of a day's close, with each holding's price that day), and a stock's live share is `w0 · (p/p0) / (S/S0)` against `^GSPC` (`liveWeight` in `convex/stonks/board.ts`), so the ranking changes hands during the day (25 stream so a 21st can climb in); `ranked()` also gives each its rank at the previous close (`baseRank`, the ▲1 by a row) and the index points it's moved the S&P today (`contribution`). Queries are split by how often they change, since every result goes to every phone: `board` (prices, every second) is small; `sparks` and `chart` change once a minute, when a minute of trading finishes onto the day's chart (`stockQuotes.minute`, `stockDayHours`), and the live price is drawn on the end on the phone; `profile` (key stats and news) every half hour. The day runs 4am to 8pm New York: a gap of hours starts a new day, and the last regular-session price (`regularPrice`) becomes the previous close; after hours shows its own change. `convex/stonks/market.ts` is the exchange's clock with holidays and 1pm closes through 2027 (shared with phones; the sidecar has the same table in `market.rs`).
- Stonks' paper trading (`convex/stonks/trade.ts` for the rules, the rest in `convex/stonks.ts`, screens in `Crew.tsx`, `Positions.tsx` and `TradeDock.tsx`): one shared game with no lobby, everyone in `users` starting at $10,000 (`stockAccounts` appears with a first order). Buy, sell, short and cover anything on Yahoo Finance (see below), as market orders in fractional shares: opening picks dollars, closing picks shares or all of it. **The fill rule is the anti-cheat:** an order never fills at the price on screen. It waits (`stockOrders`) and fills inside `stonks:ingest` on the first regular-session trade stamped after the tap (`fillWaiting`), so knowing the price from another app is no edge, whatever the feed's delay; pre-market and after-hours trades don't fill, so outside the session it waits for the open. A dollar of net worth backs a dollar of positions, long or short (`buyingPower`): no leverage, short proceeds can't be spent, and waiting orders set money aside. You can't be long and short one stock. A waiting order can be cancelled. The board leads with your money, the crew ranked by net worth live (`stonks:crew`), your positions, waiting orders and the crew's trades; a stock has your position, who else is in it, and Buy/Short (or Sell/Buy more, Cover/Short more) pinned to the bottom, opening an amount sheet. Everything's public. An order that waited over 30 seconds pushes when it fills, and a fill against a friend's position (a short or sale when they're long, a buy when they're short) pushes them. `watchlist` includes anything held or on order, so it keeps streaming if it drops out of the top 25. Not handled yet: splits and dividends, margin calls on a squeezed short, limit orders, contract sizes on futures (a future's price is treated as the price of one unit), seasons or resets.
- **Stonks and storage.** Convex keeps the old version of every row it rewrites until retention deletes it, so what fills the disk isn't what's stored but how often it's rewritten: on 2026-11-02 a day wrote about 700 MB of old versions to keep 5.7 MB of current data. So: `compose.yaml` sets `DOCUMENT_RETENTION_DELAY` to 3 days (30 by default) and `MAX_SESSION_CLEANUP_DURATION_HOURS` to 24, which bounds the database at about three days of writes, and a change to them restarts `convex` on the next deploy, since compose recreates what the rebuilt containers depend on. The window has to stay well above an hour, how often Convex saves its search index (`SEARCH_WORKERS_MAX_CHECKPOINT_AGE`), or a restart can't rebuild it, and above how long kiwi might be off: past the window, search and writes still worked in a test but index workers kept logging out-of-retention errors. The sidecar writes every trade only while someone's on a Stonks screen or an order's waiting on it (`stonks:hot`, `useHereNow`, `HeldBack` in `sink.rs`); otherwise a symbol gets one write a minute, the last trade of that minute, and whatever was held back goes in as soon as someone arrives. A day's chart is one row per hour (`stockDayHours`, `setDay`, `addMinute`), so a new minute rewrites an hour at most. A refresh that brings nothing new writes nothing (`same`), and a row's `at` is when it last changed. Before adding anything that rewrites a row often, work out what it costs a day. SQLite reuses freed pages but never shrinks the file; only `VACUUM`, with `convex` stopped, does. A restart costs memory: on 2026-11-03 `convex` came back at about 6 GiB, against about 2 GiB after running for days.
- Stonks' profiles (`src/games/stonks/Profile.tsx`, `/stonks/u/:id`, `stonks:player`; reached from a crew row, a holder, a trade's avatar, Your money, and the Crew and You tabs): a player's card with its frame, effect, badge and tagline, their frame's color spilling out behind it and on their net worth line (with their glow, and a trace of their foil or CRT over the chart), then a donut of where the money is, their positions (same rows as yours; a tap lands on the stock's page with Buy at the thumb), what's waiting to fill (read-only unless it's yours), their record and their history. On the donut a slice's size is the position's and its color is how it's doing (`gainColor`): paler for a small move, darker the bigger, in `--up` or `--down`; `--deep` keeps the darkest visible on a dark background, and the row's swatch is the slice's key. Idle money is its own slice. **Net worth history** (`stockWorth`, one row per moment holding everyone's worth): written after any fill (`writeWorth`) and every 15 minutes (`recordWorth`), skipped if nothing changed, thinned by `thinWorth` to hourly past 3 days and daily past 14; `stonks:worthHistory` returns it. There's no back-fill, so it starts when the table did. The board's Crew section is everyone on one chart (`CrewChart`), the live worth on the end of each line, and the rows are its key: a finger on the chart shows that moment in the rows. **A player's color** (`playerColors`) follows them, never their rank: their frame's color if it's free (`cardColor`), else the next `--series-N` slot in join order, dashed past eight.
- Stonks trades **everything on Yahoo Finance**: stocks anywhere, ETFs, funds, crypto, forex, futures, indexes. Search (`Search.tsx`, a box on the board; `stonks:search`) answers every keystroke from `stockSymbols` (seeded with 11,700 US listings from Nasdaq's daily files, `universe.rs`), and a moment later asks Yahoo through `stonks:lookup`, which the sidecar answers (`lookups.rs`) and which is remembered for a week; what it finds joins the list live, and any Yahoo ticker works as a link. Phones never talk to Yahoo. What can stream is everything, so what does stream is chosen: `stonks:watchlist` is the index's top 25, anything held or on order, whatever a phone reports on screen (`stonks:watching`, `report` in `warm.ts`, expiring after 90s, `sweepViews`), and the exchange rates to value them. `deepWatch`, the same minus what's merely been seen, also gets history, stats and news: a row in a search result streams its price, but charts are only fetched once you touch it. **Rate limits:** the stream is one WebSocket however many symbols are on it. Every REST request to Yahoo goes through one pacer (`rest.rs`, one per 250ms, and a 429 pauses all of it, 30s doubling to 10 minutes). Batch quotes (`snapshot.rs`, 150 symbols a request) say what each thing is and give a price to whatever isn't ticking: every 20s if its market's open and it's silent, every 5 minutes otherwise. A restart picks up from `stonks:freshness` instead of refetching. Charts nobody's opened in two weeks are deleted (`sweepSeries`). **Currencies:** a quote has its `currency`; books are kept in dollars, converted at the fill and on every read through `<CUR>USD=X` (`fxPair`, `toUsd`, and London's pence), so a currency's moves count; orders wait if the rate isn't known yet. **Hours:** the session on a tick is Yahoo's own (`marketHours`: 1 regular, 4 overnight...), so markets abroad and crypto fill in their own hours; `marketOf` says what a thing's market is doing, New York's clock for US listings and Yahoo's `marketState` elsewhere. **Late feeds:** Yahoo's Tokyo and Korea prices run 15 to 20 minutes behind with honest timestamps, and because orders fill on a trade stamped after the tap, one there simply waits that long; the screen says so ("15 min late", "Next trade, about 15 min"). Some things never tick on the stream (`ES=F`, `JPYUSD=X`, funds): a batch quote's latest regular-session trade fills their orders the same way (`stonks:snapshot`).
- The Stonks screens (`Board.tsx` and `StockPage.tsx`, loaded together through `Stonks.tsx`): the board is the S&P's chart, today's and the year's range bars, "Moving the S&P" (a diverging bar chart of index points), the top 20 (rank and its change since the close, an earnings chip that week, a sparkline, the price), market news and where it all comes from; a stock is its chart, Stats (ranges, share and rank, points moved, open, previous close, volume against normal, last trade) and its news. **Pro** (`usePro`, the round button in the nav bar, remembered per phone) adds key stats (market cap, P/E, EPS, dividend, beta, averages, short interest, margins, growth, earnings with the estimate), analysts' targets as a range bar with the mean marked, About, the 50- and 200-day averages on the 1Y and 5Y charts (with a key), and relative volume on the board. - Stonks must never make anyone wait on a tap, so: what you can tap next is already subscribed (`warm.ts`, Convex's `prewarmQuery`, renewed while wanted and never doubled): the Games card warms the board and starts its code downloading as soon as it's on screen or Play is touched (`GameCard.prefetch`); each board row (and mover) warms its stock's quote, profile and charts while it's on screen or within 120px of it (an `IntersectionObserver`, not all 25: what's visible, so it stays light); a stock warms its other ranges and the board. Up and down always carry a caret and a sign, never color alone.
- The sidecar (`stonks/src`): Yahoo's streamer first (`yahoo.rs`, unofficial, protobuf, no key; price, time, day's range and volume), Nasdaq.com polled as the standby for whatever Yahoo stops covering in the regular session (`router.rs`, `nasdaq.rs`; Nasdaq gives the last sale but not its time, so a poll only counts as a trade when the day's volume went up since the poll before, stamped with that earlier poll's time, `traded_since`, and a stale last sale never fills an order), history from Yahoo's chart endpoint on a schedule, every symbol's day first (`history.rs`; 1D every 15 minutes while trading, with pre and post, and the day's and year's stats from its meta), key stats from Yahoo's quote summary and news from its search and ticker feed (`profile.rs`; the quote summary wants a cookie from fc.yahoo.com and a crumb, refetched when refused; stats every 30 minutes and news every 10 while trading), holdings every 6 hours (`holdings.rs`), and writes at most once a second, or once a minute with nobody looking (`sink.rs`). - Real-time netcode, built this way after the first version lagged:
  - A move is a single insert into `rtCommands`. It never reads or writes the match document, so two players moving at once can't conflict.
  - Moves are stamped with the tick the player acted on (`clientTick`, clamped to `MAX_LAG_TICKS` back), so the mover's optimistic update matches the server exactly and nothing jitters.
  - The server doesn't re-validate moves. The engine ignores illegal ones identically everywhere.
  - `chess:rtTick` runs every 500ms: it advances a settled snapshot in `rtSnapshots` to `now - MAX_LAG_TICKS - 2` and finishes the game once the result falls inside the settled part.
  - Clients replay snapshot + commands (`chess:rtState`) and move pieces directly in the DOM each frame (`RealtimeGame.tsx`). React re-renders only when the board's structure changes. Remote moves ease in over `CATCH_UP_TICKS`, and the clock (`clock.ts`) slews instead of jumping.
  - Never put per-move simulation, or writes the other player also makes, back into the move mutation.
- Game routes are wrapped in `NotificationsRequired`, so links from Discord still enforce push.

## Look and feel

- Wordle-style letter tiles are the motif (`src/Tiles.tsx`). A crooked red "hit" tile marks a PvP attack.
- Opening the app never flashes white: when iOS reopens it from cold, the page paints before the stylesheet arrives, so `index.html`'s first script sets the theme, `color-scheme` and the page's color itself, from the color `src/theme.tsx` saved for that mode (`bg-dark`, `bg-light`).
- Themes live in `src/style.css` and are listed in `src/themes.ts`. Each theme defines light and dark tokens plus tile colors. Use tokens like `bg-card`, `text-muted-foreground` and `var(--tile-green)`, never raw colors, so every theme works.
- Body text is the phone's own font (SF Pro on iOS, Roboto on Android). The heading font can be changed on the You tab (Oxanium by default) and applies to `.font-display`: titles, headings, numbers, and tiles.
- iOS 26 blurs a band about 30pt deep under the status bar in standalone web apps (the scroll edge effect), and there's no way to turn it off. Chromium tests can't see it. `TopEdge` covers that band with a solid strip; keep all text below `TOP_CLEAR` (headers start at `safe-area-inset-top + 34px` or more), and never make text `sticky` or `fixed` at the top. An e2e test checks the header.
- Use Phosphor icons (`@phosphor-icons/react`, `*Icon` exports), filled for active states. Use Motion (`motion/react`) for springs, shared-layout selection, and live presence. Respect reduced motion (`MotionConfig` is set in `App.tsx`).

### Design system

The whole app follows one small system, defined at the top of `src/style.css`. Use it on every screen and every new game.

- **Type: 7 sizes.** `text-title-lg` (36, tab titles), `text-title` (28, sheet titles and big results), `text-heading` (20, section headings), `text-body` (17, the default), `text-callout` (15, secondary text and buttons), `text-footnote` (13, row details and chips), `text-caption` (11, tab labels and board coordinates). No `text-sm`, `text-xl` or pixel sizes. `cn()` (`src/lib/utils.ts`) knows these names, so they merge correctly.
- **Radius: 4 steps.** `rounded-sm` 8px (board, tiles, icon squares), `rounded-md` 12px (compact controls), `rounded-lg` 16px (rows, groups, big buttons, cards), `rounded-3xl` 28px (sheets and dialogs). `rounded-full` only for avatars, status chips and icon buttons.
- **Surfaces.** Group rows in one flat `Group` (`src/components/parts.tsx`): `bg-card`, `rounded-lg`, dividers, no outer border and no shadow. Never put cards inside cards. Section headings are `font-display text-heading`, never small grey labels.
- **Layout.** Tabs open with `LargeTitle`; pushed screens use `NavBar` (back, centered title, one action) from `src/components/AppHeader.tsx`. Primary actions sit where thumbs reach them. Game screens are a compact bar on top, the board and its players as one block in the middle, and actions docked at the bottom; keep heights under the board fixed so nothing shifts it.
- **Navigation.** `src/shell.tsx` makes it feel like a native stack: tabs switch instantly, pushed screens slide in from the right and out on Back, a swipe from the left edge goes back (iOS standalone apps have no swipe-back of their own), and each history entry keeps its scroll position. Back (`useGoBack`) steps back through in-app history (`history.state.idx`); a screen opened fresh from a push or link has none, so it goes to its fallback, which for games is Home.
- **Motion.** Press feedback is `active:scale-[0.97]` over 100ms. Screens and sheets use springs with no bounce; a little bounce only for celebrations. Nothing loops while idle: no wiggling icons, pulsing dots or breathing avatars. The exceptions are live signals (someone typing or on the board right now), user-chosen card frames, the real-time countdown, and a tile you're holding. Games should feel alive when something happens; it's idle screens that stay still. Don't use shared-layout (`layoutId`) moves for things that would cross the board; they catch taps on the way.
- **Sheets** dim the screen behind them (`bg-black/40`) instead of blurring it. Use them for small focused things (a player's card, promotion, editing your card), never for game menus; those are full pages.
- **No filler text.** No subtitles under titles, no explanatory sentences under headings, no empty-state prose. Say it with the heading or the control; show a section only when it has content. Real information (a mode under a player's name, a rating, a record) is fine.
- **Status.** Online is a steady green dot (`bg-online`); offline shows no dot, since red reads as an error. Turn state is a chip: `Your move` in the primary color, everything else quiet.
- **Results** are spelled in tiles: WON in green, LOST with a crooked red hit tile, DRAW in yellow, places for four players.
- Choosing one of a few options is `Segmented` (`src/components/Segmented.tsx`); don't hand-roll another.
- **Shared parts.** Build screens from these, and when a game needs something twice or a second game needs it, move it here instead of copying it:
  - `src/components/ui/`: shadcn's `button` (with the `card` variant, and `dock`/`dock-square` sizes for game docks), `alert-dialog`, `drawer`, `input`, `switch`, `skeleton`, `sonner`, `playing-card`; ours: `sheet` (`Sheet`, the only way to make a bottom sheet: title, optional close X, body padded clear of the home indicator), `slider`, `disclosure` (a row that folds something away; `Rules` and the settings use it).
  - `src/components/`: `parts.tsx` (`Section`, `SectionTitle`, `Group`, `Chip`, `MatchRow`, `TurnChip`, `ResultChip`, `InviteCard`, `RankTile`, `Leaderboard`), `ListRow` (leading, title, detail, trailing; a link with `to`, a button with `onClick`), `PlayerAvatar` (pass `player`; `online` adds the dot) and `AvatarStack`, `AsyncButton`/`usePending`, `ConfirmButton` (anything destructive: Resign, Cancel game, Sign out), `AmountSheet` (how much: poker's bets, Stonks' orders), `Segmented`, `GameMenu`, `Rules`, `SettingsPicker`, `AppHeader` (`LargeTitle`, `NavBar`, `useGoBack`).
  - `src/components/game/`: what game screens share. `GameFrame` (board block plus dock) and `DockNote`, `floating.tsx` for fullscreen games (`FullscreenStage`, `FloatingTopBar`, `FloatButton`, `FloatPill`, `useFullbleed`), `TurnText`/`useTurnText` ("Chris is on it"), `SeatDot`.
  - `src/components/match/`: the lobby, the result with standings and rematch, and `ResignButton`.
  - Hooks and helpers: `src/presence.tsx` (`usePresence`, `useHere`, `OnlineDot`, `ThinkingDots`), `src/lib/time.ts` (`ago`, `useNow`), `src/lib/serverClock.ts` (`useServerClock`, for anything real-time), `src/lib/text.ts`, `src/games/seats.ts` (`SEAT_COLORS`, `seatColor`), `src/games/types.ts` (`Player`).
- Presence: `convex/presence.ts` stores a heartbeat, the screen each player is on, and their latest tap. `src/presence.tsx` shows online dots and other players' taps on the main tabs; game screens use the path to say who has that game open right now ("here now", "is on it").
- Player cosmetics (frame, frame color, glow, effect, badge, tagline) are in the `profiles` table, with options in `convex/profileOptions.ts`. Name and avatar come from Discord on every sign-in and are not editable.

## Running it locally

`dekit` on a fresh clone runs the whole app, with only Node and Docker installed (`dekit.yaml`, `scripts/dev.mjs`, how to use it in `README.md`): the Convex backend in Docker, `convex dev`, Vite on 5173, `og` on 8788, the sidecar, and `test/*` tasks. It doesn't touch kiwi, even in a checkout whose `.env.local` has kiwi's keys: `scripts/dev.mjs` names the local backend to the CLI outright, and environment variables beat that file.

- **Sign-in without Discord.** `VITE_DEV_AUTH=1` (set on `web`) shows `DEV_CREW` instead of the Discord button, keeps each tab's session in `sessionStorage` so each tab is its own player, and skips `InstallGate` and `NotificationsRequired`. It's absent from every real build. `DEV_AUTH=1` on the deployment turns on the `dev` Convex Auth provider (`convex/devAuth.ts`), which also requires `CONVEX_SITE_URL` to be on this machine, so it stays off on kiwi even if the variable gets set there. Never set either on kiwi. These players aren't `isTest`, so they behave like real ones.
- **Ports.** The dev backend doesn't publish its site port: tokens are checked from inside the container, and it leaves host port 3211 for `npm run test:e2e`, which can run while dekit's up.
- **The sidecar** runs with `cargo run` in `rust:1-alpine` inside the backend's network (`--network container:`), so it needs no Rust installed and no port tricks. Its build lives in the `group53-dev-target` volume, shared with `test/sidecar`.
- `dekit start test/smoke` (`scripts/dev-smoke.mjs`) checks the running stack in a real browser. After changing the boot steps, try them on a real fresh clone.

CI (`.github/workflows/ci.yml`) runs on every PR and push to `main`: the typecheck, `npm test` (with Bun, so golf's cross-engine check runs), the build, the sidecar's `cargo test`, and the full e2e suite, with one retry on CI (a test that only passed on its retry shows as flaky). It never deploys.

### Deploy

```sh
npm test && npm run test:e2e   # both must pass
git add -A && git commit && git push origin main
npm run deploy
```

`npm run deploy` (`scripts/deploy.sh`) refuses to run with uncommitted changes (`-- --dirty` overrides; don't use it for real releases). It then:

1. pushes the Convex functions (`npx convex deploy -y`);
2. rsyncs the repo to `kiwi:~/Services/group53/`, skipping `node_modules`, `dist`, `.git`, `secrets`, `.env*`, `.convex` and test output;
3. rebuilds and restarts the `web`, `og` and `stonks` containers (`docker compose up -d --build web og stonks`);
4. prunes the untagged images each rebuild leaves behind, plus build cache older than a week;
5. checks `/`, `/version.json` and `/sw.js` on `https://group53.shlokbhakta.dev` answer 200;
6. checks `/version.json` now names a different build than before the deploy, and fails if it doesn't. That new ID is what makes phones show "Updating" and reload.

It's done when it prints `Build <old> -> <new>` and `Live: {"id":"..."}`, and the log shows `✔ Deployed Convex functions`. Phones pick up the new build on their own (`src/version.tsx`): an "Updating" overlay, a reload, then "You're up to date".

### Order of changes

Convex functions go live before the web app does. Additive backend changes (new functions, new optional args, new fields) are safe in one deploy. Removing or renaming a function, or making an arg required, crashes phones still running the old app: ship the frontend that stops using it first, then remove the function in a later deploy. Schema changes that drop or retype fields need a migration first.

### On kiwi

The stack is `~/Services/group53` (a copy, not a git checkout). `compose.yaml` runs six containers, about 440 MB of RAM together:

- `convex`: the whole backend (database, functions, websockets, scheduler, real-time tick). SQLite on the SSD.
- `web`: nginx serving the built app (`Dockerfile` builds with Node, then keeps only `dist/` and nginx, about 5 MB of RAM). `nginx.conf` also sends link-preview bots to `og`, falls back to `index.html` for deep links, caches `/assets/` for a year, and never caches `sw.js` or `version.json`.
- `og`: a small Node server for Discord and Open Graph link previews. Bots can't run the app's JavaScript, so `og` reads live data from Convex and returns the tags plus a PNG card: satori lays the card out as SVG, resvg turns it into PNG. It isn't a backend for the app; the app talks to Convex directly.
- `stonks`: the stonks sidecar (Rust, about 8 MB of RAM, an empty image with one binary). It streams prices into Convex with the admin key (`secrets/admin_key`, like `og`). `docker compose logs stonks` shows which source is covering what.
- `tunnel`: Cloudflare Tunnel `group53-games`, which puts the three public hostnames online without opening ports on kiwi.
- `dashboard`: the Convex web dashboard on the tailnet. Nothing depends on it; the CLI does the same jobs.

Deploys only rebuild `web`, `og` and `stonks`; the other three keep running.
