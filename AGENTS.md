# Group 53 Games

Small multiplayer games for one friend group from Discord. Chess (classic, four-player, and real-time versions of both) and Scrabble (2 to 8 players, async or live with a turn timer) are live; PvP Wordle is next. Every game lives in the same app.

## Who this is for

- **At most 5 players, maybe 10.** Never design for scale. A full table scan, a query that returns everyone, or a cron that touches every row is fine. Use this headroom to make the games richer, not to optimize.
- **Phones only.** Everyone plays from the installed PWA on iOS or Android. Desktop only needs to not break. Design for thumbs: tap targets at least 44px, primary actions 56px, nothing important in tiny menus, and confirm anything destructive.
- **Everyone is a software developer.** Programmer jokes and references land, and so do themes like Catppuccin, Gruvbox and Nord.
- **Low friction.** Every extra tap or screen costs players. Prefer one-tap actions, sensible defaults, and flows that resume where people left off.

## Design principles

- **Lean on Convex's live updates.** Every query is a live subscription: when the database changes, every connected client re-renders instantly. Build features on that. Show other players' moves the moment they happen, presence ("Chris is typing a guess"), live scoreboards, attacks landing on your board in real time, and animations triggered by someone else's action. If a feature could be live, make it live.
- **Spend compute freely.** The group is tiny, so server work is basically free. Recompute derived state on every change, fan out notifications generously, render images on demand, and schedule as many functions as needed.
- **Make it interactive and PvP.** Games should let players affect each other: sabotage, steal, block, taunt. Async is fine, since games run over a day rather than in one sitting, but whatever is happening should feel live.
- **Notifications are core.** Push is how players hear they've been hit or that it's their turn. Games stay locked until push is on. When something happens to a player, notify them.
- **Discord is home.** Players sign in with Discord, links get shared in Discord, and link previews should show live game state (see `og/`).

## Stack

- React 19, Vite, React Router, Tailwind v4 and shadcn/ui (Radix). Components are in `src/components/ui`; use them instead of hand-rolled controls.
- Self-hosted Convex on kiwi with SQLite, plus Convex Auth with the Discord provider.
- Web push through `web-push` in a Node action (`convex/push.ts`).
- `og/`: a small Node service that renders Discord and Open Graph previews with satori and resvg.

## Games framework

Adding a game means: its modes in `convex/modes.ts`, its hooks in `convex/games.ts`, its server file (`convex/<game>.ts`), and its entry in `src/games/index.tsx`. Everything else is shared.

- `convex/modes.ts` (shared by server and client) lists `GAMES` (name and path) and every mode. Each mode is `async` (turn-based over hours) or `realtime` (everyone on screen at once), has `players` (most seats) and `minPlayers`, and its `settings`.
- **Seats.** When `minPlayers` equals `players` (chess) the game starts by itself once full. When they differ (Scrabble, 2 to 8) the lobby waits for the host to tap Start (`matches.startGame`), and it also starts by itself if every seat fills. Challenges in these games leave the other seats open without pinging the crew.
- **Settings.** Each mode lists its settings (choices with a default, each a number, plus a `short` summary like "9 tiles"). The host picks them on the mode page (remembered per mode on the phone) and can still change them in the lobby (`matches.configure`, which merges only the keys sent), where everyone sees them change. `matches.settings` stores only what differs from the defaults; read it with `settingsOf(mode, match.settings)`. Rematches keep the settings. Chess has: Time to move (classic: none, 1, 2 or 3 days, losing on time; four-player: 1 to 3 days, default 2), and real-time Cooldown and Piece speed (`State.pace` in the engine). Scrabble has the settings listed under Scrabble below.
- **Game hooks** (`convex/games.ts`): `seats` (seat colors in turn order), `start` (set up `state`, whose turn, first pushes), `resign`, `timeout` (an async move timer ran out) and `timeoutWarning`. `matches.ts` calls these and never names a game. Hooks are looked up at call time because the game files import `matches.ts`.
- **Secrets** (`secrets` table): state players mustn't see. Per player (`userId` set; a Scrabble rack) or the game's (no `userId`; the tile bag). Only ever returned to its owner; never put hidden information in `matches.state`, since everyone can read that.
- **Drafts** (`drafts` table): a player's plan for their next move, saved as they go, so it's there when they come back. Private, but `count` lets others see that someone is planning.
- Paths come from `matchPath(match)`, `acceptPath(match)` and `modePath(mode)`, which use the game's path (`/chess/...`, `/scrabble/...`). Never hard-code a game's path.
- `convex/matches.ts` is game-agnostic and works for any seat count: open lobbies and the queue (`queue` joins someone waiting or opens a lobby and pings the crew), challenges to one or more players (invite fewer than the seats and the rest are `openSeats` for the crew; invited players keep their seat until they answer, and in bigger games a decline opens the seat instead of cancelling), join, leave, decline, cancel, resign, draw offers (two-player only), `finish` (results with `standings` for multiplayer, ratings, placing pushes), rematches (everyone has to say yes; colors move one seat along), and the `lobby`, `attention` and `inbox` queries. Mode-specific state lives in `matches.state`.
- Client side, `src/games/index.tsx` (`GAME_UI`) gives each game its Games card art, mode art, rules (a function of the settings) and the in-game screen. Routes are generated from it in `App.tsx`: `/<game>` is `GameHub` (`src/pages/GameHub.tsx`), `/<game>/mode/:slug` is `ModePage`, and `/<game>/:id` is `MatchScreen`, which shows the shared lobby (`src/components/match.tsx`: seats, settings, Start, share, cancel) or the game's own screen. The result, standings with points, rating change, rematch and the resign confirmation are shared there too. Lists that can mix games label modes "Chess Classic", "Scrabble Live" (`fullModeLabel`).
- Four tabs (`src/components/TabBar.tsx`, a full-width bar whose active pill slides between tabs): **Home** (`src/pages/Home.tsx`), **Games** (`src/pages/Games.tsx`), **Crew**, and **You** (profile and settings).
- Home is built on `matches.inbox`, across every mode: Challenges (answered in place), Your turn, Open seats, Your ratings (stat cards from `ratings.mine`, only modes you've played), Waiting, and Happening now (`watch`). A section only appears when it has something in it; with nothing going on, Home shows an idle tile row and a Find a game button.
- Games has one card per game with its art playing in once (`ChessBanner`, the WORDLE tiles), who's playing it right now, and Play. Play opens the game's own pages; nothing about starting a game is a drawer.
- A game's page (`GameHub`) shows the mode cards from `ModePicker` (`src/components/ModePicker.tsx`), grouped Async and Real-time, each with its art, a badge when something waits there, and my Elo; a game with one mode of each kind shows the two side by side. Then the crew's recent games of it (`matches.recent`). The mode page is the full-page menu for one mode: Find a game (joins a waiting game or opens one for the crew; "Open a game" for games the host starts), Settings, Challenge (the crew inline: two-player modes send on one tap, bigger games let you pick several), How to play, open seats, your games, games happening now, the mode's leaderboard, and recent games. Old `/chess?mode=` and `/?new=` links land on the mode page.
- Leaderboards live on each mode's page, not on Crew, so adding games never piles more tabs or pills onto one screen.
- Each mode has one name, used everywhere: Classic, 4-Player, Real-time, Real-time 4-Player (`MODES[mode].name`).
- The app icon shows a badge: my moves plus challenges waiting (`navigator.setAppBadge`). Pushes carry the count (`badgeCount` in `convex/notify.ts`, set in `public/sw.js`), and `useAppBadge` keeps it right while the app is open. It works on iOS 16.4+ home screen apps once notifications are allowed.
- Deep links: challenge and lobby pushes point at `acceptPath` (`/chess/:id?accept=1`), and opening that takes the seat. Notification taps reach the app through `public/sw.js`, which posts `{type: "navigate"}` to an open window (iOS standalone apps ignore `WindowClient.navigate()`) and also leaves the URL in the Cache API, which `src/deepLinks.ts` picks up when the app opens fresh at its start page. Links shared in Discord open in a browser, not the app: iOS can't open a home screen web app from a link at all, and Android only sometimes can (Discord's in-app browser usually keeps the link). That browser isn't signed in either. So a game link opened outside the app shows the link page (`src/components/LinkHandoff.tsx`, above the install steps): the game, then the crew's faces under "Which one's you?". Tapping yours pushes the game to your phone (`links.handoff`, at most once every 15 seconds per player), and the notification opens the app right in it and takes the seat. Android also gets an "Open in the app" button (an `intent://` link), and the manifest asks Chrome to capture links into the installed app (`handle_links`, `launch_handler`). `links.preview` and `links.handoff` work signed out on purpose and only show what a Discord link preview already does. Challenges also wait on Home.
- Async turns: every move pushes the next player, and `scheduleReminder` re-arms an 8-hour reminder. Reminders carry the move count they were set for and fizzle if anyone has moved since, so they never need cancelling.
- `notify()` (`convex/notify.ts`) skips the push when the player is already looking at that URL. Pushes carry a `tag` per match so they replace each other.
- Ratings: Elo per mode in `convex/ratings.ts` (K=32, start 1200). Multiplayer games count every pair of players as a game between them, weighted K/(n-1), by placing (`multiElo`). The leaderboard lists the whole crew.
- Async chess (Classic and 4-Player) never sends a move straight off the board: the move waits on that phone, shown as the position after it with a faint copy of the piece at home, and Confirm (naming the move) and Cancel take the place of draw and resign in the dock (`src/games/chess/dock.tsx`). While it waits you can move another piece instead, or move the same one back home to take it back. A move landing, a resignation or a timeout drops it. Real-time chess moves at once.
- Chess: `convex/chess.ts`. Classic is validated with chess.js. Real-time follows rtchess.org (Kung Fu Chess) and runs on a deterministic engine in `convex/chess/realtime.ts`, shared by server and client: 30 ticks/s, 1 square per second, 5s cooldown, collision captures, premoves (a busy piece queues one move that fires when it's ready; a `cancel` command drops it), take the king to win. Keep the engine free of Convex and browser imports.
- Four-player chess (chess.com Free-for-all) lives in `convex/chess/four/`: `board.ts` (14x14 minus 3x3 corners; red, blue, yellow, green clockwise; each army's setup is red's rotated) and `classic.ts` (the turn-based engine: check against every opponent, checkmate/stalemate put you out, grey armies stay on the board and score nothing, points for captures and multi-checks, most points wins, ties by who lasted longer). `chess:fourMove` validates with it; in four-player, resigning or six missed reminders (48 hours, `TIMEOUT_STRIKES`) puts you out and play goes on. The real-time engine takes a `variant` ("two" or "four"): in four-player, losing your king (or a `resign` command) freezes your army in grey, there's no castling, and the last king standing wins with a ranking by elimination tick.
- Scrabble: `convex/scrabble.ts` on top of `convex/scrabble/engine.ts`. The rules (legal plays, the words a play forms, scoring with bonus squares, blanks and the 50-point bingo, letter values, the bag, the standard board) come from `@bglowacki/bingo-engine` (MIT, pinned to 0.1.0), wrapped in `evaluate()`, which turns our free-form placements (tiles on any squares) into the engine's line-plus-tiles form. On top of it we add a 21×21 board (our own layout, handed to the engine as its `BoardLayout`) and a Letter League rules mode (`LEAGUE` in the engine; the same engine, board and word list with Letter League's changes on top). So far that's sticky bonuses ("Wild" scoring): a bonus square stays with its tile, so every later word through it scores it again, scored from the engine's per-word cell breakdown. Add further Letter League rules to `LEAGUE`. The engine runs with a dictionary that accepts anything; the server checks words against `convex/scrabble/words.ts` (ENABLE, public domain, plus qi/za/ok/ew; server-only, regenerate with `scripts/gen-words.sh`) through `isWord`, and phones ask `scrabble.check` for the live preview. Settings: Tiles in hand (5/7/9; a bingo is the whole rack), Tiles in the bag (Half to 200), Board (15×15 or 21×21), Rules (Scrabble or Letter League), Rounds (no limit, 5, 10, 15), and Time to move (async, skips you when it runs out) or Turn timer (live, 30s to 3m; `scrabble:turnTimeout` skips the turn). It ends when someone goes out with the bag empty (they get everyone's leftover tiles), when everyone has passed twice in a row, or after the last round; leftover tiles count against their holder. Places by score, and Elo through `multiElo`. Resigning puts your tiles back in the bag and you place last; the rest play on.
- The Scrabble screen (`src/games/scrabble/`), laid out like Letter League: a game in progress takes the whole screen (`fullscreen` in `GAME_UI`, so `MatchScreen` leaves out its nav bar). The board is the whole background, running under the status bar (the page sets `data-fullbleed`, which hides `TopEdge`), and everything else floats over it: a back button, a pill edged in the color of whoever's turn it is (their avatar with its frame, the last play and the live clock), and a menu button on top (`Chrome.tsx`), and a see-through dock at the bottom. The board knows how much of it the bars cover (`view.padTop`/`padBottom`): any square can be panned into the open part between them, and drops only land in that open part. The menu slides in from the right: everyone's score, whose turn it is and who's planning, the words played (tap one for its definition, from dictionaryapi.dev), how to play, and Resign, kept away from the buttons you tap all game. The dock holds your rack and, under it, the bag (tiles left; tap it for every letter you haven't seen yet), Swap (pick nothing and it becomes Pass), Play (which names the word and score) and Shuffle or Recall. A finished game goes back to the board above the result. The board (`Board.tsx`) pinches, double-taps and drags to zoom and pan (moves go straight to the DOM), starts zoomed in on the action, and glides to a new word that lands out of view. Tap a rack tile then a square, or drag it (it sits right under your finger); tap a placed tile to send it back, drag it to move it, and drag over the rack to reorder. Plans work any time, even on someone else's turn, are saved as drafts (a moment after each change), and come back on any phone; a tile whose square someone else takes goes back to your rack with a toast. Like Letter League, whoever's turn it is shows up on everyone else's board as face-down tiles in their color where they're trying things (`scrabble.planning` returns squares, never letters), appearing and vanishing in little puffs. The score bubble and tile outlines are green for real words and red otherwise. Blanks ask for their letter in a small sheet. Tiles are physical cream tiles in every theme (`.stile` in `style.css`), edged in the color of whoever played them. It should feel alive: a played word drops in tile by tile and bounces in time with its notes, its score floats up in the player's color, the scores pop as they change, tiles thunk onto the board and spring when moved, a held tile jiggles and leans the way you drag it, shuffling makes the rack hop, words that aren't real shake, and a bingo spells BINGO over the board.
- Sound (`src/sound.ts`): everything is synthesized with Web Audio, so there are no files. Effects come in packs (Wood, the default, Thock, Kalimba, Felt piano, Glass, Bubbles, Soft, Arcade, or Off), each three voices (click, note, thump) that every sound is built from (`sfx("place")`, `"play"`, `"land"`, `"turn"`, `"invalid"`, `"bingo"`, `"tick"`, `"win"`...), so swapping packs changes the whole game. Background music is generative (Lo-fi, the default, Late night, Sunday, Coffee shop, Rain, Drift, Music box, Arcade, or Off) and plays all over the app once you're signed in (`wantMusic` in `App.tsx`). Everything runs through a small room reverb, with a send per pack and track. Both are picked from lists on the You tab: a track switches the music right away, a pack plays a two-second little game in it. Remembered per phone. Keep new packs and tracks at Wood's and Lo-fi's level: soft envelopes, filtered noise for anything percussive, a few sine partials for anything tonal, and reverb rather than loudness. "Play on silent" (on by default) sets the audio session to "playback", which plays with the ringer off but pauses other audio; off, it's "ambient", which mixes with other apps and goes quiet with the silent switch. iOS only unlocks audio from a whole tap (touchend or click), and wants a sound started in that tap, so `wake()` plays a silent buffer and resumes the context on every tap until it's running; music starts from the context's `statechange`. Tests read `window.__sfx` (effects asked for) and `window.__music` (the track playing), and `window.__soundLab` renders any sound or track offline so the e2e suite checks every one for silence and clipping.
- Boards are drawn through a `View` (`src/games/chess/geometry.ts`) so every player sees their army at the bottom; on the 14x14 board taps snap to the nearest useful square, since squares are under 30px.
- Real-time netcode, built this way after the first version lagged:
  - A move is a single insert into `rtCommands`. It never reads or writes the match document, so two players moving at once can't conflict.
  - Moves are stamped with the tick the player acted on (`clientTick`, clamped to `MAX_LAG_TICKS` back), so the mover's optimistic update matches the server exactly and nothing jitters.
  - The server doesn't re-validate moves. The engine ignores illegal ones identically everywhere.
  - `chess:rtTick` runs every 500ms: it advances a settled snapshot in `rtSnapshots` to `now - MAX_LAG_TICKS - 2` and finishes the game once the result falls inside the settled part.
  - Clients replay snapshot + commands (`chess:rtState`) and move pieces directly in the DOM each frame (`RealtimeGame.tsx`). React re-renders only when the board's structure changes. Remote moves ease in over `CATCH_UP_TICKS`, and the clock (`clock.ts`) slews instead of jumping.
  - Never put per-move simulation, or writes the other player also makes, back into the move mutation.
- Game routes are wrapped in `NotificationsRequired`, so links from Discord still enforce push.
- Link previews for `/chess/:id` and `/scrabble/:id` render the live board, including the four-player cross and the Scrabble board with scores (`convex/previews.ts` and `og/server.mjs`). Check them with `node e2e/og-preview.mjs`.

## Look and feel

- Wordle-style letter tiles are the motif (`src/Tiles.tsx`). A crooked red "hit" tile marks a PvP attack.
- Themes live in `src/style.css` and are listed in `src/themes.ts`. Each theme defines light and dark tokens plus tile colors. Use tokens like `bg-card`, `text-muted-foreground` and `var(--tile-green)`, never raw colors, so every theme works.
- Body text is the phone's own font (SF Pro on iOS, Roboto on Android). The heading font can be changed on the You tab (Oxanium by default) and applies to `.font-display`: titles, headings, numbers, and tiles.
- iOS 26 blurs a band about 30pt deep under the status bar in standalone web apps (the scroll edge effect), and there's no way to turn it off. Chromium tests can't see it. `TopEdge` covers that band with a solid strip; keep all text below `TOP_CLEAR` (headers start at `safe-area-inset-top + 34px` or more), and never make text `sticky` or `fixed` at the top. An e2e test checks the header.
- Use Phosphor icons (`@phosphor-icons/react`, `*Icon` exports), filled for active states. Use Motion (`motion/react`) for springs, shared-layout selection, and live presence. Respect reduced motion (`MotionConfig` is set in `App.tsx`).

### Design system

The whole app follows one small system, defined at the top of `src/style.css`. Use it on every screen and every new game.

- **Type: 7 sizes.** `text-title-lg` (36, tab titles), `text-title` (28, sheet titles and big results), `text-heading` (20, section headings), `text-body` (17, the default), `text-callout` (15, secondary text and buttons), `text-footnote` (13, row details and chips), `text-caption` (11, tab labels and board coordinates). No `text-sm`, `text-xl` or pixel sizes. `cn()` (`src/lib/utils.ts`) knows these names, so they merge correctly.
- **Radius: 4 steps.** `rounded-sm` 8px (board, tiles, icon squares), `rounded-md` 12px (compact controls), `rounded-lg` 16px (rows, groups, big buttons, cards), `rounded-3xl` 28px (sheets and dialogs). `rounded-full` only for avatars, status chips and icon buttons.
- **Surfaces.** Group rows in one flat `Group` (`src/games/chess/parts.tsx`): `bg-card`, `rounded-lg`, dividers, no outer border and no shadow. Never put cards inside cards. Section headings are `font-display text-heading`, never small grey labels.
- **Layout.** Tabs open with `LargeTitle`; pushed screens use `NavBar` (back, centered title, one action) from `src/components/AppHeader.tsx`. Primary actions sit where thumbs reach them. Game screens are a compact bar on top, the board and its players as one block in the middle, and actions docked at the bottom; keep heights under the board fixed so nothing shifts it.
- **Navigation.** `src/shell.tsx` makes it feel like a native stack: tabs switch instantly, pushed screens slide in from the right and out on Back, a swipe from the left edge goes back (iOS standalone apps have no swipe-back of their own), and each history entry keeps its scroll position. Back (`useGoBack`) steps back through in-app history (`history.state.idx`); a screen opened fresh from a push or link has none, so it goes to its fallback, which for games is Home.
- **Motion.** Press feedback is `active:scale-[0.97]` over 100ms. Screens and sheets use springs with no bounce; a little bounce only for celebrations. Nothing loops while idle: no wiggling icons, pulsing dots or breathing avatars. The exceptions are live signals (someone typing or on the board right now), user-chosen card frames, the real-time countdown, and a tile you're holding. Games should feel alive when something happens; it's idle screens that stay still. Don't use shared-layout (`layoutId`) moves for things that would cross the board; they catch taps on the way.
- **Sheets** dim the screen behind them (`bg-black/40`) instead of blurring it. Use them for small focused things (a player's card, promotion, editing your card), never for game menus; those are full pages.
- **No filler text.** No subtitles under titles, no explanatory sentences under headings, no empty-state prose. Say it with the heading or the control; show a section only when it has content. Real information (a mode under a player's name, a rating, a record) is fine.
- **Status.** Online is a steady green dot (`bg-online`); offline shows no dot, since red reads as an error. Turn state is a chip: `Your move` in the primary color, everything else quiet.
- **Results** are spelled in tiles: WON in green, LOST with a crooked red hit tile, DRAW in yellow, places for four players.
- Choosing one of a few options is `Segmented` (`src/components/Segmented.tsx`); don't hand-roll another.
- Presence: `convex/presence.ts` stores a heartbeat, the screen each player is on, and their latest tap. `src/presence.tsx` shows online dots and other players' taps on the main tabs; game screens use the path to say who has that game open right now ("here now", "is on it").
- Player cosmetics (frame, frame color, glow, effect, badge, tagline) are in the `profiles` table, with options in `convex/profileOptions.ts`. Name and avatar come from Discord on every sign-in and are not editable.

## Testing

Run both suites before shipping, and add tests with every feature.

- `npm test`: Vitest. `convex/*.test.ts` run Convex functions with convex-test (helpers in `convex/test.setup.ts`). `src/themes.test.ts` parses `style.css` and fails if any theme is missing a token or has text below WCAG AA contrast in light or dark mode.
- `npm run test:e2e`: Playwright at iPhone size against a throwaway Convex backend in Docker (`e2e/backend.mjs`). It uses the same image as kiwi, runs on host port 3211, and the app is previewed on 4573. Fixtures in `e2e/fixtures.ts` create signed-in players through `convex/testing.ts`, emulate the installed PWA, and fake push. The suite covers the install gate, notifications locking games, live presence and taps across two phones, who has a game open, card edits, themes, sign-out, 44px tap targets, the tab bar, edge swipe-back, the app icon badge, old links landing on mode pages, axe accessibility scans, and full chess games on two phones (classic moves, drag, checkmate, challenges accepted from Home, leaderboard, real-time countdown and simultaneous moves, king capture ending the game through the scheduler, spectators), Scrabble on two phones (`e2e/scrabble.spec.ts`: the game page and settings, the host changing settings live in the lobby, playing words, plans surviving a reload, face-down tiles on the other phone, sounds and music, sound settings, every sound and track rendered and checked, the full-screen layout with its dock, bag, menu and pass-by-swap, made-up words refused, drag and drop, and the live turn clock), and four-player games on four phones (`e2e/four.spec.ts`: the chess page and mode cards, accepting through a push link, Home and a service-worker message, board rotation, resigning, standings, four-way rematches, real-time with everyone moving at once, and the cold-start deep link).
- First run: `npm run test:e2e:install` to download Chromium. If GitHub's registry is unreachable, copy the backend image from kiwi: `ssh kiwi docker save ghcr.io/get-convex/convex-backend:latest | docker load`.
- `SCREENS=1 npm run test:e2e -- screens` (and `-- scrabble-screens`, a four-player Scrabble game) writes review screenshots to `e2e/.state/screens` in dark and light mode. Look at them before shipping UI changes.
- `convex/testing.ts` only works where `ALLOW_TEST_HELPERS=1`. Never leave it set on kiwi: only `e2e/load.mjs --prod` turns it on, for the length of a run, and it switches it off again (a watchdog does this even if the run hangs). Test players carry `users.isTest`: they never receive pushes and never trigger pushes to real players. `testing:removeTestData` deletes only them and their games; `testing:reset` refuses to run while real players exist. For Scrabble, `testing:setRack`, `testing:rackOf` and `testing:playAs` give a player known tiles and play words for them.
- `node --experimental-strip-types e2e/load.mjs` is a real load test: real `ConvexClient` websockets, signed sessions, presence, taps, simultaneous real-time and classic games. It reports move latency, how long a move takes to reach the opponent, errors, and server conflict retries by function. With no flag it uses a throwaway local backend; `--prod` hits kiwi through Cloudflare. A baseline from 2026-10-25 on prod with 12 players: real-time move p50 115ms, p95 207ms; reaching the opponent p50 115ms, p95 209ms.
- Themes are generated by `scripts/gen-themes.py`. Change colors there, then regenerate the theme block in `style.css`.

## Working on it

- Golf (async only) is being explored as a single-player prototype that isn't in the app yet, in the direction of Putt Party and GamePigeon: hand-made holes drawn flat, straight down (`toy.ts`: no depth or shadows), in one of three looks being tried: pixel art in the PICO-8 or Sweetie 16 palette (drawn at about 5.5 pixels per unit, every pixel snapped to the palette, then scaled up unsmoothed) or smooth. The smooth course is always the same natural golf colors (warm muted greens with diagonal mowing stripes, a cream painted rail, terracotta bumpers, bunker sand); the void and dot grid behind it take the app theme's `--background` and `--border`, and the explorer injects the app's theme blocks from `src/style.css` so its menus follow the theme too. Two courses: Bumper Plains (`src/games/golf/plains.ts`, six short holes built round bumpers in inconvenient places, with a few speed pads) and Battle Grounds (`battle.ts`, three big holes after Super Battle Golf: minefields, speed-pad highways, jump ramps across gaps in the void; the camera follows the ball and leans toward the cup). Items come from mystery boxes, three at a time: ours (Ghost, Magnet, Brake, Mulligan, Big cup, Jump, Bouncy) and Super Battle Golf's, made to work on a ball (Rocket Driver, Spring Boots, Golf Cart, Jumbo Burger, Smoke Bomb, and the targeted Orbital Laser, Landmine and Rail Gun). Air Horn, Flash Camera and Thunderstorm wait for multiplayer. `engine.ts` is the deterministic physics (240 steps/s, so async play can replay others' shots; keep it free of browser imports), `audio.ts` is golf's own sound, and `GolfExplorer.tsx` is the screen. The hole generator (`gen.ts`, `render.ts`, `courses.ts`) is parked: it works, but generated holes felt uncanny next to hand-made ones. `npm run golf:build` builds the explorer into one self-contained file, `prototypes/golf/dist/golf.html`, separate from the app's build and deploy.

- Convex data lives on kiwi's SSD (`/home/shlok/ssd-data/group53/convex-data`). The 5TB USB disk (`usb1`) is an SMR spinning drive. On it, commits stalled for 0.5–1.2s and logins took seconds, so never put a database there.
- Every async button uses `AsyncButton` or `usePending` (`src/components/AsyncButton.tsx`). They lock while running and show a spinner, so double taps can't duplicate actions. Mutations that create things should also be idempotent on the server, like `challenge`.
- New deploys reach phones on their own, and every phone always runs the newest build: `version.json` carries the build ID, and `src/version.tsx` checks it on launch, every minute, when the app comes back to the foreground, and on navigation. A new build covers the app with an animated "Updating" overlay, reloads, and shows "You're up to date" from the bottom when it's back. Nothing is lost (games are on the server, Scrabble plans save within a fraction of a second); only a real-time chess game in progress holds the update (`useHoldUpdates`) until it ends. If a reload doesn't land on the new build (a stale cache), it offers an Update toast instead of looping.
- Toasts sit below the band iOS blurs under the status bar. Sonner uses `mobileOffset` on phones, not `offset`, so set both.
- Discord OAuth needs `issuer: "https://discord.com"` on the provider (`convex/auth.ts`), or every sign-in fails on the `iss` check.

## Shipping

Work happens one agent at a time on `main`. When a feature is done: run both test suites, commit, push to `origin main`, then deploy. The user has said to do all of that without asking.

### Before the first deploy

- The repo is at `~/Projects/group53-games` (T3 also sees it as `~/.t3/projects/group53-games`, a symlink). GitHub: `git@github.com:Shlok-Bhakta/group53-games.git`.
- `.env.local` (gitignored, only on this machine) holds `CONVEX_SELF_HOSTED_URL`, `CONVEX_SELF_HOSTED_ADMIN_KEY` and `VITE_CONVEX_URL`, pointing the Convex CLI at kiwi over Tailscale (`http://100.88.30.127:38441`). If it's missing, the admin key is in `kiwi:~/Services/group53/secrets/admin_key`.
- `ssh kiwi` must work without a prompt (an alias in `~/.ssh/config`: user `shlok` at `100.88.30.127`, so Tailscale has to be up). Check with `ssh -o BatchMode=yes kiwi true`.

### Deploy

```sh
npm test && npm run test:e2e   # both must pass
git add -A && git commit && git push origin main
npm run deploy
```

`npm run deploy` (`scripts/deploy.sh`) refuses to run with uncommitted changes (`-- --dirty` overrides; don't use it for real releases). It then:

1. pushes the Convex functions (`npx convex deploy -y`);
2. rsyncs the repo to `kiwi:~/Services/group53/`, skipping `node_modules`, `dist`, `.git`, `secrets`, `.env*`, `.convex` and test output;
3. rebuilds and restarts the `web` and `og` containers (`docker compose up -d --build web og`);
4. prunes the untagged images each rebuild leaves behind, plus build cache older than a week;
5. checks `/`, `/version.json` and `/sw.js` on `https://group53.shlokbhakta.dev` answer 200;
6. checks `/version.json` now names a different build than before the deploy, and fails if it doesn't. That new ID is what makes phones show "Updating" and reload.

It's done when it prints `Build <old> -> <new>` and `Live: {"id":"..."}`, and the log shows `✔ Deployed Convex functions`. Phones pick up the new build on their own (`src/version.tsx`): an "Updating" overlay, a reload, then "You're up to date".

### Order of changes

Convex functions go live before the web app does. Additive backend changes (new functions, new optional args, new fields) are safe in one deploy. Removing or renaming a function, or making an arg required, crashes phones still running the old app: ship the frontend that stops using it first, then remove the function in a later deploy. Schema changes that drop or retype fields need a migration first.

### On kiwi

The stack is `~/Services/group53` (a copy, not a git checkout). `compose.yaml` runs five containers, about 430 MB of RAM together:

- `convex`: the whole backend (database, functions, websockets, scheduler, real-time tick). SQLite on the SSD.
- `web`: nginx serving the built app (`Dockerfile` builds with Node, then keeps only `dist/` and nginx, about 5 MB of RAM). `nginx.conf` also sends link-preview bots to `og`, falls back to `index.html` for deep links, caches `/assets/` for a year, and never caches `sw.js` or `version.json`.
- `og`: a small Node server for Discord and Open Graph link previews. Bots can't run the app's JavaScript, so `og` reads live data from Convex and returns the tags plus a PNG card: satori lays the card out as SVG, resvg turns it into PNG. It isn't a backend for the app; the app talks to Convex directly.
- `tunnel`: Cloudflare Tunnel `group53-games`, which puts the three public hostnames online without opening ports on kiwi.
- `dashboard`: the Convex web dashboard on the tailnet. Nothing depends on it; the CLI does the same jobs.

Deploys only rebuild `web` and `og`; the other three keep running.

```sh
ssh kiwi 'cd Services/group53 && docker compose ps'                    # what's running
ssh kiwi 'cd Services/group53 && docker compose logs --tail 100 web'   # or og, convex, tunnel
ssh kiwi 'cd Services/group53 && docker compose restart og'            # restart one service
```

Convex function logs: `npx convex logs` from this repo. The dashboard is on the tailnet at `http://100.88.30.127:38443` (log in with the admin key). Data is on the SSD at `/home/shlok/ssd-data/group53/convex-data`; never move it to the USB disk.

### Convex environment variables

Set on the deployment, not in files: `npx convex env list`, `npx convex env set NAME value`. In use: `JWT_PRIVATE_KEY`, `JWKS`, `SITE_URL`, `AUTH_DISCORD_ID`, `AUTH_DISCORD_SECRET`, `VAPID_SUBJECT`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`. `ALLOW_TEST_HELPERS` must stay unset on kiwi (see Testing).

### Rolling back

Revert the bad commit (`git revert <sha>`), push, and run `npm run deploy` again. It's a full redeploy of that tree, backend included, so the same ordering rules apply: if the bad commit removed a function the old app needs, reverting brings it back.

### Link previews

If a change touches `og/` or `convex/previews.ts`, check the cards after deploying with `node e2e/og-preview.mjs`.
